# SDE Career Positioning Framework

## 1. Purpose

This document defines how the candidate's verified experience should be positioned for the target role (typically Software Development Engineer / Software Engineer).

It is a **positioning strategy**, not a source of new candidate facts.

The candidate profile remains the factual source of truth. This document determines:

* Which verified experiences receive emphasis
* How different experiences connect into a coherent professional story
* Which technical themes should be foregrounded
* Which experiences should be secondary or omitted
* How positioning should adapt to different role descriptions for this candidate
* Which positioning mistakes must be avoided

## 11. Keywords From Job Descriptions

Job descriptions should determine **emphasis**, not factual content.

For every JD:

1. Extract required and preferred technologies.
2. Map them against the candidate's verified evidence.
3. Identify exact matches.
4. Identify adjacent/relevant experience.
5. Identify missing technologies.
6. Prioritize verified matches in the resume.
7. Do not add missing technologies merely for matching.

---

## 12. Missing-Skill Handling

When a target role contains technologies the candidate does not possess, the resume should not attempt to hide the gap through keyword substitution.

Instead:

* Maximize relevant adjacent evidence.
* Use verified transferable engineering concepts.
* Preserve truthful positioning.
* Avoid unsupported claims.

The unmet technology itself must not be claimed.

## 16. Evidence Hierarchy

When choosing between possible resume statements, prefer evidence in this order:

1. Verified engineering outcome
2. Verified engineering decision/problem solved
3. Verified implementation
4. Verified technology usage
5. General responsibility
6. Generic skill claim

## 17. Omission Strategy

Omission is preferable to weak or distracting information.

Potentially omit:

* Non-substantive assignments
* Unverified metrics
* Unverified technologies
* Generic personal skills
* Low-relevance technologies
* Unsupported off-role claims

The goal is to present the strongest truthful evidence for the target role.

## 20. IMMUTABLE POSITIONING CONTRACT

This file controls **positioning only**. It does not authorize the generator to invent facts or alter the template.

## Positioning may change

For each role, the generator may:

- emphasize different verified experience
- select different verified bullets
- reorder verified evidence within an allowed section
- use truthful role terminology
- de-emphasize less relevant verified material

## Positioning may NOT change

The generator MUST NOT:

- change the candidate's primary identity
- create a new job title
- convert project experience into professional experience
- convert exposure into expertise
- convert adjacent skills into claimed technologies
- create leadership or ownership claims
- create metrics or business impact
- change the candidate's career history
- change the resume section order
- redesign the visual template

## JD boundary

The role description is a **relevance signal only**.

It answers: **What verified evidence should receive more attention?**

It does NOT answer: **What does the candidate know or have experience with?**
