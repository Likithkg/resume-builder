# Reference Resume Visual Template Specification

## 1. Purpose

This document defines the visual and structural template that must be preserved when generating the candidate's SDE resume.

The reference resume is used **only as a visual/template source**.

No candidate facts, names, education, projects, achievements, or other personal information from the reference resume may be transferred to the candidate's resume.

---

# 2. Page Format

## Page Size

**US Letter**

* Width: approximately 612 pt
* Height: approximately 792 pt
* Equivalent to 8.5 × 11 inches

The reference document contains **2 pages**. This is a visual source only. The candidate's approved resume MUST be exactly **1 page**. Do not reproduce the reference's two-page length.

---

# 3. Margins

The reference content begins approximately at:

* Left: **28.8 pt**
* Right: **28.8 pt**

This corresponds to approximately:

**0.4 inch left/right margins**

The content area therefore extends approximately from:

**x = 28.8 pt to x = 583.2 pt**

Do not substantially increase the margins.

The compact horizontal layout is part of the visual identity.

---

# 4. Header / Candidate Name

The candidate name is centered horizontally at the top of the page.

## Name

Reference characteristics:

* Center aligned
* Bold
* Approximately **20.7 pt**
* Black
* Positioned near the top of the page
* Approximately 27 pt from the top content origin

For the generated resume:

**LIKITH K G**

should occupy the same visual role.

Do not add a profile photo, colored banner, graphical header, icons, or decorative elements.

---

# 5. Contact Information

The reference places contact information immediately beneath the candidate name.

Characteristics:

* Center aligned
* Approximately **10.9 pt**
* Regular weight
* Black
* Compact spacing below the name
* Contact elements appear on a single line where possible
* A small diamond separator is used between contact elements

Reference structure:

```text
Phone ⋄ Email
```

For the candidate resume, use the verified contact information in the same general structure.

Do not introduce:

* Colored icons
* Social-media icons
* Large contact blocks
* Address paragraphs
* Decorative graphics

GitHub and LinkedIn may be included when their actual URLs are verified, while preserving the compact header structure.

---

The reference uses a **Computer Modern / LaTeX-style typeface family**.

Observed font characteristics include:

* Regular body: `CMR10`
* Bold text: `CMBX10` / `CMBX12`
* Italic text: `CMTI10`
* Symbol/bullet font: `CMSY10`

# 8. Section Headings

Section headings use:

* Uppercase text
* Bold weight
* Approximately 10.9 pt
* Black
* Left aligned
* Compact spacing
* Clear separation from the previous section

Examples from the reference include:

```text
OBJECTIVE
EDUCATION
COURSES
TOOLS USED
PROJECTS
PERSONAL SKILLS
EXTRA CURRICULAR ACTIVITIES
```

The final resume should use the same visual treatment.

---

# 9. Section Heading Position

Section headings begin near the left page margin.

Approximate reference x-position:

**28.8 pt**

Section content begins farther inward.

Approximate content x-position:

**45.2 pt**

This creates approximately:

**16.4 pt indentation**

between the section heading and the section's body content.

Preserve this visual relationship.

---

# 10. Section Content Indentation

Most section content begins approximately at:

**45.2 pt**

from the left page edge.

This is approximately:

**0.63 inch**

from the page edge.

The section heading remains farther left at approximately:

**28.8 pt**

This indentation is an important structural characteristic of the template.

---

# 11. Section Spacing

The reference uses compact vertical spacing.

Typical structure:

```text
SECTION HEADING

    Content
    Content
    Content

NEXT SECTION
```

Avoid large gaps between sections.

The resume is designed to maximize usable information while maintaining readability.

---

# 12. Body Text

Body text characteristics:

* Approximately 10.9 pt
* Regular Computer Modern style
* Black
* Left aligned
* Approximately 13.5 pt line-to-line vertical progression in many sections
* Compact paragraph spacing

Long descriptions may wrap naturally across multiple lines.

Do not use large paragraph spacing.

---

# 13. Line Spacing

The reference body text has a compact line spacing.

Observed vertical progression is approximately:

**13.5 pt per line**

For example, body lines often occur around:

```text
y = 107.9
y = 121.5
```

which gives approximately:

**13.6 pt**

Use approximately this density unless necessary for technical rendering.

---

# 14. Dates

Dates are generally aligned to the **right side of the content area**.

Reference right boundary:

Approximately:

**583.2 pt**

Entry content occupies the left side while dates occupy the right.

Conceptually:

```text
Degree / Position                                      Date
Institution / Company
Additional information
```

Preserve this two-sided structure wherever dates are used.

---

# 15. Experience / Education Entry Layout

The reference uses a strong left/right hierarchy.

Example structural pattern:

```text
PRIMARY ENTRY TITLE                                  DATE

Supporting organization / location
Additional information
```

For the candidate's experience:

```text
Software Engineer                                   August 2024 – Present
Tata Consultancy Services (TCS), Bengaluru, India
```

The exact ordering should be adapted to the candidate's information while preserving the reference's visual alignment.

---

# 16. Bold Text

Bold is used selectively.

Appropriate uses include:

* Major entry titles
* Degree names
* Section headings
* Candidate name
* Important entry labels

Do not make entire paragraphs bold.

Do not use bold for every ATS keyword.

---

# 17. Italic Text

Italic styling is used for secondary labels.

The reference contains examples such as:

```text
Mini Project
Major Project
```

These use an italic visual treatment.

Use italic sparingly for secondary metadata when appropriate.

Do not use italic for major technical content.

---

# 18. Bullets

The reference uses a small centered-dot style bullet.

Observed bullet:

```text
·
```

The bullet is positioned slightly to the left of the body text.

Approximate structure:

```text
   ·  Description of the item
```

The bullet itself uses a symbol font.

For the final resume, preserve the simple small-dot appearance.

Do not replace it with:

* Large circles
* Checkmarks
* Arrows
* Colored bullets
* Decorative icons

---

# 19. Bullet Indentation

Reference bullet position is approximately:

* Bullet x-position: **36.7 pt**
* Text begins around: **39.7–45.2 pt**, depending on wrapping

Wrapped lines generally align with the main content indentation rather than creating excessive hanging indentation.

Maintain compact bullet indentation.

---

# 20. Bullet Density

Bullets are compact and information-dense.

The final resume should:

* Avoid excessive vertical gaps between bullets
* Avoid paragraph-style blocks where bullets are appropriate
* Keep each bullet focused on one contribution
* Allow natural wrapping
* Avoid oversized bullets

Content density should resemble the reference rather than a modern spacious resume.

---

# 21. Projects

The reference presents projects using a hierarchy:

```text
PROJECT TITLE
Project type / secondary label

· Description
```

The project title is bold.

The secondary descriptor may be italic.

The description begins with a small bullet.

For the candidate:

```text

[secondary information if appropriate]

· Description
```

and:


should follow the same visual hierarchy.

# 22. Skills / Tools Sections

The reference can present skills or tools as compact vertically stacked entries.

For the candidate, the skills section should remain visually consistent with the reference while being adapted for SDE content.

Do not create:

* Two-column skill grids
* Skill bars
* Rating stars
* Progress meters
* Logos
* Visual proficiency indicators

# 23. Section Ordering

The reference uses clearly separated uppercase sections.

The candidate section order is IMMUTABLE and MUST be: OBJECTIVE → EDUCATION → EXPERIENCE → SKILLS / TOOLS → PROJECTS → ACHIEVEMENT. The target JD may change emphasis and wording inside these sections, but MUST NOT reorder, rename, add, or remove sections except where this document explicitly permits it.

Recommended candidate structure:

```text

EDUCATION

EXPERIENCE

PROJECTS

ACHIEVEMENT
```

Sections MUST NOT continue onto page 2. The final candidate resume is one page.

The visual treatment must remain consistent.

# FINAL ENFORCEMENT PATCH — LAYOUT v3 — DETERMINISTIC BLOCK MODEL

The resume is rendered from fixed blocks. The generator must populate blocks; it must not redesign them.

## Fixed block schema

Allowed blocks are: OBJECTIVE body; EDUCATION degree/institution with dates; EXPERIENCE employer/title/date, location, bullets; SKILLS / TOOLS category/value lines; PROJECTS title, technology metadata, bullets; ACHIEVEMENT body. No block may be converted to another block type to solve overflow.

## Alignment classes

- Section headings: x approximately 28.8 pt.
- Main content: x approximately 45.2 pt.
- Bullets: marker approximately 36.7 pt.
- Experience dates: right aligned to the outer content boundary.
- Experience location: left aligned with main content.
- Project title: left aligned with main content.
- Project technology line: LEFT aligned with main content. NEVER right aligned.
- Project bullets: same bullet geometry as experience bullets.
- Achievement body: main content start.

## Project integrity rule

Every project MUST render as: (1) project title, (2) project technology line, (3) project bullet(s). A technology line without its title is a fatal error. A project title may never disappear during compression.

## Section integrity rule

Every required section must retain its heading and required content block. Do not allow a heading to survive after its content is accidentally dropped.

## One-page compression order

When overflow occurs: shorten Objective; shorten bullets without changing facts; remove lower-priority experience bullets; remove lower-priority skills; shorten project detail; omit a lower-priority project only if section integrity remains valid. Never alter geometry, alignment, typography, or section order.

## Machine-checkable fatal failures

Reject the artifact if project technology metadata is right aligned, a project title is missing, any main content block starts at the heading boundary instead of the main content boundary, section order changes, the artifact exceeds one page, or forbidden visual elements appear.
